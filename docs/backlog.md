## Open — navigation scope gaps (raised 2026-09-01, evidence in docs/NAVIGATION_RESEARCH.md)

- [critical][pitch] **The route figure's baseline is a strawman.** `isih/figures/route_map.png` compares our route against a great-circle straight line, which no captain sails. Real state of the art is a master routing on *yesterday's observed ice* (PolarView/AMSR2 charts) plus ~100 nmi helicopter recon. Replace with the baseline ladder: same router, ice input = {observed-persistence, raw GLORYS12 forecast, our corrected forecast} — see docs/NAVIGATION_RESEARCH.md §5.
- [critical][eval] **Route-regret hindcast is unbuilt and is the highest-value experiment in the project.** Plan on day 0 under each ice input, then replay the voyage through the ice that *actually* occurred and score real transit time / fuel / cells the ship could not enter. This is what converts "18–31 % lower SIC error" into days and tonnes. It can come out against us — see docs/NAVIGATION_RESEARCH.md §5.
- [critical][routing] **PolarRoute's router has no time dimension — verified by source grep.** The mesh is one frozen snapshot; the ship is assumed to meet day-0 ice on day 17. A static router structurally cannot consume a lead-time forecast, so our model's value is currently unexpressible in the route. Needs a time-expanded mesh stack: edge = (cell, t) → (neighbour, t + traveltime) — see docs/NAVIGATION_RESEARCH.md §2 Gap 2.
- [major][routing] **PolarRoute's `wave_resistance()` is dead code in all three vessel classes** — defined, never called; `model_resistance` sums only wind + ice. Waves act solely as a binary `swh > max_wave` cutoff, so there is **no sea-state fuel penalty anywhere**, including the Roaring Forties where most fuel burns. ML_ARCHITECTURE.md:620's planned Golovnin subclass "with wave resistance" will silently do nothing unless `model_resistance` is also overridden. Latent bug: the dead method reads `params["Beam"]`/`["Length"]` but `__init__` sets `"beam"` — see docs/NAVIGATION_RESEARCH.md §2 Gap 1.
- [major][routing] **`max_ice_conc: 80` is a threshold we invented.** IMO MSC.1/Circ.1519 (POLARIS) is the mandated framework and gives `RIO = Σ(Ci × RIVi)` with published RIV tables per ice class and thresholds 0 / −10, plus speed caps (PC1 11 kt … below PC5 3 kt). Full tables extracted — see docs/NAVIGATION_RESEARCH.md §1.
- [major][ml] **POLARIS forces a thickness output.** RIO is indexed by WMO *ice type*, not concentration, and stage-of-development maps to thickness. So SIC alone cannot produce a POLARIS-compliant route. GLORYS12 carries `sithick`; the U-Net extends to a second output channel without architectural change — see docs/NAVIGATION_RESEARCH.md §1.
- [major][routing] **Open-ocean phase (port → ice edge) is entirely unbuilt**, and it is half the problem statement. Good news: meshiphi already ships `era5_sig_wave_height`, `era5_max_wave_height`, `era5_wave_period`, `era5_wind`, `gebco` and an `icenet` *forecast* loader — the data plane exists, only the cost model is missing. Reuse, do not build a second engine — see docs/NAVIGATION_RESEARCH.md §2.
- [major][routing] **Two-phase seam has no design.** Optimising open-ocean and ice phases independently picks the wrong ice-edge entry point. Proposed: solve the ice phase *backwards* from the station to a cost-to-go field over the ice edge, then run open-ocean routing forward with that field as terminal cost (Bellman). Not yet an ADR.
- [major][ml] **Persistence is regime-dependent, so the +18–31 % headline is not a fixed target.** The post-2016 low-extent state is documented as having *different seasonal persistence characteristics*. Gains must be reported per-regime, not pooled, and 2016/2023 should be explicit held-out OOD test years — see docs/NAVIGATION_RESEARCH.md §4.
- [major][eval] **No forecast-error growth check under climate drift.** Nothing yet trains on a trailing climatology anomaly rather than raw SIC, and nothing monitors innovation-channel drift in production to widen uncertainty when the world leaves the calibration distribution. The daily CMEMS cron is the right infrastructure; it is not wired to anything.
- [minor][routing] **Multi-vessel / fleet effects are dismissed in COMPETITIVE_ANALYSIS.md §2 ("no commercial traffic, no fixed lanes") and that is only half right.** Congestion in Antarctica is *temporal* (everyone wants the same Dec–Apr window) and the scarce resource (a lead) is shared, so recommending one route to every user manufactures correlated failure. POLARIS §1.6.4 gives the mechanism for the opposite effect too: a following ship may add **+10 to RIO** along a broken track. Minimum viable answer is k-diverse routes with per-route passability, not a single line.
- [minor][pitch] **Do not put "Goa → Antarctica by sea" on a slide as current practice.** Expeditions are flagged off from Goa but personnel fly to Cape Town, where the chartered vessel starts the sea leg. An Indian-port departure is credible as *forward-alignment* with the GRSE/Kongsberg indigenous PRV (MoU June 2025), not as today's operation — see docs/NAVIGATION_RESEARCH.md §3.
- [minor][routing] Route smoothing exists in PolarRoute (`crossing_smoothing.py`, Newton relaxation of cell crossings) and we are not demonstrably using or reporting it — a raw Dijkstra polyline has kinks no hull can steer.
- [minor][ux] Output is a single line with a point ETA. For a decision-support system it should be a corridor with a passability probability, an ETA distribution, flagged decision points where ensemble routes diverge, and escape/abort options against besetting.

## Open — IMO Polar Code Ch.11 compliance gaps (raised 2026-09-03)

Polar Code Part I-A §11.3 lists what a master **must** consider when planning a
polar route. Five of the nine factors are things we do not do. This section
exists because these are not feature requests — they are the regulation the
system claims to support.

- [resolved][scope] **Bharati sits *inside* ASMA 6 — now modelled, and the fix this line recommended would have been wrong.** Resolved 2026-09-07 in commit 641e20f (`isih/protected_areas.py`). The line proposed wiring the polygons through PolarRoute's `excluded_zones` hook as no-go geometry. Reading the legal regime first says otherwise: Environmental Protocol Annex V Art. 3 gates ASPA *entry* on a permit, Art. 4 requires no permit for an ASMA, and **zero of the 33 corridor polygons are flagged marine**, so none restricts the vessel's transit — they bind shore operations. Treating ASMAs as no-go would have refused to route to India's own station. Confirmed by point-in-polygon in EPSG:3031: Bharati inside ASMA 6, ASPA 174 Stornes 1.9 km, ASPA 169 Amanda Bay 28.4 km, and — not previously recorded — ASPA 163 Dakshin Gangotri, India's own, 4.7 km from Maitri. Counts corrected: 148 polygons = 142 ASPA + 6 ASMA, over 77 unique ASPAs.
- [minor][data] **Do not reach for CCAMLR MPAs for this corridor** — corrects an assumption made earlier the same day. The only two adopted MPAs are South Orkney and Ross Sea, both far outside 0–80°E, and they restrict *fishing*, not transit. CCAMLR's GeoServer does carry `gis:aspa`/`gis:asma` layers but they are a partial marine subset (12+2 features) and would silently miss Stornes. Treat the ATS shapefile as authoritative.
- [minor][compliance] **MARPOL Annex I Reg. 43 bans heavy fuel oil south of 60°S** — carriage *and* use, mandatory since 1 Aug 2011, SAR/safety exempt. The whole route is inside it, so the vessel runs MGO/MDO. A single latitude test, no polygon needed. Distinct from Reg. 43A, which is the Arctic ban (MEPC.329(76), in force 2022) — do not conflate.
- [minor][scope] **No IMO Area To Be Avoided exists in Antarctic waters** — checked against IMO's own polar-shipping page; every IMO polar routeing measure is Arctic. The Antarctic-specific instrument is Res. A.999(25), which is recommendatory voyage-planning guidance, not a geographic exclusion. Do not claim to honour an ATBA that does not exist.
- [minor][ops] **The responsible MRCC changes partway along this corridor, near 75°E.** South Africa's maritime search-and-rescue region runs to the South Pole then along 75°E (gazetted, No. 51132/Notice 5162, 30 Aug 2024). Maitri at 11.7°E is inside it; **Bharati at 76.2°E is roughly 50 km outside**, presumably in Australia's — their matching primary source was not retrieved, so confirm before use. Only South Africa's boundary is pinned to citable coordinates; the other four sectors exist as a map with no published degree table.
- [minor][ops] **Nearest capable asset to Bharati is Russian, not Indian.** Progress station is 5–10 km away with Zenit Airfield (3,000 m, Il-76-capable, Cape Town in 6.5 flight hours) and a medical unit described as a regional hospital. Near Maitri, SANAE IV is ~530 km west and is *legally* a South African Maritime Rescue Sub-Centre. COMNAP's own best case for help arriving is 5–6 sailing days; Akademik Shokalskiy took 8–9 days with three nations responding, for a ship that was only beset.
- [minor][data] **A 2026 Sentinel-1 iceberg catalogue reaches 0.016 km², about 4,000× finer than USNIC's 68.6 km² floor** (Jiao et al., doi:10.25959/54sx-pt47, published 25 Aug 2026; also Chen/Liu at 0.04 km², Zenodo 10.5281/zenodo.17165466). Both free and GIS-ready. This is a real upgrade to the iceberg layer. It does **not** touch the growler problem — still ~800× coarser than a growler — so §4 of TRUE_CLAIMS.md stands unchanged.
- [minor][data] **CMEMS publishes a 1 km Antarctic sea-ice product we are not using** — `SEAICE_ANT_PHY_AUTO_L3_NRT_011_012`, daily, S1 SAR + AMSR2 fusion, DOI 10.48670/mds-00320. That is 25× finer than the 25 km field we currently reason about. It is an **observation, not a forecast** — worth knowing before anyone assumes it replaces the forecast chain.
- [minor][data] **There is no dedicated Antarctic sea-ice forecast system in CMEMS.** The Arctic has one (neXtSIM); Antarctica is served only by the global `GLOBAL_ANALYSISFORECAST_PHY_001_024`, 10-day horizon, sea ice bundled into the global physics run. Anything claiming a regional Antarctic ice forecast is claiming something that does not exist.
- [minor][data] **Check our forward data path against the NSIDC retirements.** NSIDC-0051 stopped forward processing 31 Dec 2025 and NSIDC-0081 (NRT SSMIS) was retired 18 June 2026. `isih/download_nsidc.py` pulls **G02202_V6**, a different product, so training data is unaffected — but confirm the near-real-time route an operational system would use still exists on the same DMSP SSMIS stream.
- [minor][data] **IBCSO v2 is only 23.79% direct measurement south of 50°S, and its own paper names East Antarctica as singlebeam-dominant** — which is exactly this corridor, while Drake Passage and the Ross Sea get the multibeam coverage. Depth-based routing must not be trusted at face value near Bharati, Maitri or Prydz Bay: apply the planned TID-conditional margin *plus* a flat buffer near charted coastline.
- [minor][compliance] **New IMO searchlight requirement lands inside our window.** MSC.532(107)/MSC.538(107) require two remotely rotatable, bridge-controlled narrow-beam searchlights covering 360° for ice detection in darkness — new ships 1 Jan 2026, **existing ships 1 Jan 2027**. Relevant because it is IMO conceding that radar alone does not find ice, which is the same argument behind our detection-degradation advisory.
- [minor][research] **The shaft-power idea has a published blueprint on a directly comparable ship.** SA Agulhas II was instrumented with shaft strain gauges over a 68-day Antarctic voyage: hydrodynamic torque 145.0–310.7 kNm at 3.8–6.6 kn, in 2–59% concentration and 35–110 cm thickness (PMC6140293). Telemetry a diesel-electric vessel already logs, processed entirely onboard, transmittable at any bandwidth.
- [minor][scope] **Traffic volume confirms the instinct not to route toward other ships.** 255 unique vessels across the *entire* Southern Ocean 2014–2018, 88% of visits in the Peninsula/South Shetlands (Leihy et al., PNAS 119(3), 2022). The Indian Ocean sector is in the remaining 12%. There is no off-the-shelf Antarctic vessel-density product; any traffic layer must be built from raw satellite AIS. Satellite AIS revisit is *better* at high latitude than at the equator, since polar orbits converge toward the poles.
- [major][scope] **No places of refuge and no SAR-remoteness awareness — §11.3.5 and §11.3.9.** The system cannot say who to call or how far help is. Static data, zero bandwidth, ships inside the voyage pack. Needs the COMNAP/MRCC Antarctic sector table and nearby-station assets.
- [major][scope] **Prior-year statistical ice data is never surfaced — §11.3.4.** We hold 1,096 real daily files and use them only as training data. The captain never sees climatology, so "what should I expect here in late December" is unanswerable.
- [major][model] **We model scalar concentration; §11.3.3 wants extent *and type*.** This single gap blocks three separate things: POLARIS compliance (RIV is indexed by ice type), any AIRSS-style ice-numeral arithmetic, and any WMO egg-code output. Fixing the thickness/stage channel fixes all three — see the roadmap item in TRUE_CLAIMS.md §5.
- [major][scope] **The ship's own sensors are unused.** Shaft power/torque is a *measured* ice resistance and would calibrate `force_limit`, the one number `isih/ice_meshes.py` admits is borrowed from another hull. Speed-through-ice vs predicted is a free daily model validation. The ship's anemometer bias-corrects ERA5, which under-reads by −3.89 m/s above 20 m/s — precisely the winds that beset ships. **MV Vasiliy Golovnin carries two helicopters used for ice air reconnaissance on the route**; that observation has no path into the system.
- [minor][ux] **Output uses no ice-navigator vocabulary.** WMO egg code is Ct over Ca/Cb/Cc over Sa/Sb/Sc over Fa/Fb/Fc, concentration in tenths, with standard bands (7–8/10 = close pack). An advisory should read "9/10 close pack, thick first-year, ridged", not "lots of ice". MANICE Ch.3 has the full code tables.
- [minor][design] **Re-plan cadence is undefined and no regulator defines one** — the Polar Code delegates monitoring cadence to the ship's own PWOM (§2.3.6). Anchors to pick from: the Canadian Ice Service's *Rapid Closing of Coastal Leads Warning* uses **12 h** as its own threshold for a lead closing; free drift is reportedly predictable ~2 days under active forcing; Antarctic charts refresh weekly (USNIC daily for concentration only). Choose a staleness clock and write it down.
- [minor][design] **Departure-versus-underway mode split is not implemented.** At departure the system should argue its route against the captain's; once he has chosen, it must stop re-litigating the strategic choice and switch to micro-adjustments and things he can miss. A system that keeps arguing for a rejected route gets switched off.
- [minor][ux] **No detection-degradation advisory.** We cannot see growlers and TRUE_CLAIMS.md §4 promises we never will — but we *can* forecast when the lookout is blind: Bowditch says growlers are "lost in a sea greater than four feet", and blizzard visibility is ≤100 m by AAD's own definition. Converts an honest limitation into a real output without claiming to see anything.
- [minor][scope] **Traffic awareness for mutual assistance is missing** — distinct from the fleet-correlation item above. Knowing which ships and icebreakers are nearby is a safety output; it must **not** become a routing cost term, or the router will prefer busy water for the wrong reason.
- [minor][ops] **Ballast to ice draught is not advised.** The CCG manual has it as an explicit pre-departure decision. It is an advisory output, not a routing constraint.
- [minor][design] **No path for a tactical imagery request.** The *request* is a few bytes uplink; the *image* is what the link cannot afford. Ship asks, shore fulfils into the next pack. Fits the two-tier split exactly.
- [minor][research] **Do not cite AIRSS as applicable.** TP 12259E §1.1.1 ties the Ice Numeral entirely to the Canadian Arctic Shipping Safety Control Zones. POLARIS is its harmonised descendant and the only one of the three IMO-recognised systems with Antarctic scope, via the bipolar Polar Code. The arithmetic is instructive; the jurisdiction is not ours.
- [minor][research] **MV Vasiliy Golovnin had ice difficulty on this corridor in 2019** — "had difficulty getting free of the ice pack on her return voyage". Our ship, our route, but a single trade-press sentence with no official investigation. Verify with FESCO or NCPOR before it appears in any deck.
- [minor][research] **No published NCPOR, AAD, BAS or AWI ice-routing SOP could be found.** The Canadian Coast Guard manual is the only real published ice-routing doctrine located anywhere, and it is Arctic-sourced. Its strategic-ashore / tactical-onboard split, and its placement of the routing recommendation with the shore ice desk, independently match our two-tier architecture — worth citing for exactly that reason.

- [major][ml] **One seed means no error bar.** Fine for the headline table, useless for comparing arms that differ by a few percent — which is exactly what the forcing-supplier comparison (ERA5-at-t vs Aurora vs GFS) will produce. A 1.9 M-parameter model makes 3+ seeds cheap; run them before any adopt/reject decision on forcing.
- [major][pitch] **"We couldn't afford to run a foundation model" is a losing answer and appears nowhere it should.** The defensible argument is information-theoretic: the entire 1979-present daily SIC record is ~17k frames of ~1e5 pixels, far too small for the scale premise that motivates foundation models, so a ~2 M-parameter CNN saturates it. Argue from the problem, not the GPU budget — see docs/research/MODEL_REUSE_MATRIX.md §3.
- [major][ml] **The forcing layer, if built, serves three consumers, not one** — the SIC U-Net, the Wagner iceberg drift model (which currently declares a sensitivity sweep because we had no winds), and route weather exposure. Design it as a pluggable service benchmarked foundation-model vs NWP vs persisted analysis, not as "we integrated Aurora"; the first expert question is "why not ECMWF open data?" — see MODEL_REUSE_MATRIX.md §2.
- [minor][ml] **Feed the wind-advected first guess, not raw wind.** Semi-Lagrangian advection of SIC(`t`) by the free-drift rule (~2% of 10 m wind, deflected left in the Southern Hemisphere) is simultaneously a stronger baseline than persistence and a better input channel, because it encodes physics the CNN would otherwise infer from ~1,000 days. Verify coefficient and turning angle against Thorndike & Colony before publication.
- [minor][research] **IceNet (Andersson et al., Nature Communications 2021, BAS) is our closest prior art and is cited nowhere.** Reported as a purpose-built U-Net at 25 km for sea ice — i.e. the field's own choice for this target was a small U-Net, not a foundation model, which is the strongest available support for our architecture. Verify hemisphere, temporal resolution and whether an Antarctic variant exists before citing.
