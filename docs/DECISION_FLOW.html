What I changed, and why

Ordered by how much each one matters if a judge traces the flow with a finger.

IssueSeverityFix
The routes appeared from nowhere. The flow went straight from correcting the forecast to “Draw recommended route”. Nothing built a mesh; nothing ran a router. Critical Added Build vessel-modelled ice mesh (meshiphi + the Golovnin config) and Compute candidate routes (PolarRoute × 12 sweep → dominance filter). This is the single biggest omission — it is the actual navigation engine.
No uncertainty ever reached the decision. The U-Net produced a corrected forecast and the gate consumed it as if it were exact. Critical Added Add calibrated safety margin (stratified conformal q̂) producing SIC_upper. Uncertainty propagating into the route is your headline differentiator; it was invisible in the flow.
A hard YES/NO gate with no hysteresis means any forecast wobble flips the recommendation — the whipsaw you explicitly did not want. Critical Added the τ gate: suggest a change only when Cost(current) − Cost(alt) > τ, with τ drawn from the same conformal interval. Below τ, the Captain's plan stands.
“Draw recommended route and two backups to captain” appeared twice — once after YES and again after the weather step. Readability Removed the duplicate. There is now one output box, reached by one path.
“Analyze weather forecast ahead” sat after routing. Waves and wind change what a route costs; reviewing them afterwards cannot change the answer. Accuracy Moved it into the parallel input band so it prices the route. Your wording kept verbatim.
POLARIS is not what the code does today. isih/ice_meshes.py:47 uses a flat 80% concentration cutoff and notes that production replaces it with an IMO POLARIS RIO calculation. Accuracy Kept your box text, tagged it TODAY: FLAT 80% CUTOFF. Claiming POLARIS compliance in front of an examiner who asks to see the RIO table would be a bad thirty seconds.
“Sent to the applications backend” reads like a network call — which contradicts the whole two-tier design. Accuracy Annotated: the backend is local, on the bridge laptop, with no outbound network. Same box text, no ambiguity.
Two steps were labelled “AI model” without naming a model, and one of them is not machine learning at all. Accuracy Each step now names its file. Iceberg drift is tagged PHYSICS, not machine learning — a closed-form solution with 23/23 tests is a stronger claim than a vague “AI model”, and it survives cross-examination.
The confidence self-check does not exist in the codebase. Nothing compares yesterday's forecast to today's observation. Honesty Kept it — it is a good idea — but drawn dotted and tagged NOT BUILT YET, like the other two designed steps.
